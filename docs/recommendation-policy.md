# 训练推荐规则 · 1.0.0

阶段 5 更新：浏览器现已使用 localStorage 保存档案、IndexedDB 保存计划／记录／草稿，刷新不再重置。实际训练可填写器械标识和可用档位；生成新建议时使用最近完成记录中的同器械信息。修改器械时应使用不同标识。下文关于“第四阶段会话内存”的表述记录当时的实施边界，当前操作以 docs/stage-5.md 为准。

本文件解释第四阶段的确定性推荐算法。它使用当前档案、已核对动作、指定的本地日期和已有记录；相同输入得到相同输出。默认值是应用起始模板，需要根据实际表现调整。

## 研究依据与产品策略

ACSM 在 2026 年的官方更新中强调规律训练、个体化安排，以及训练量与目标之间的关系。例如，增肌目标通常需要考虑每个肌群的每周总训练量，而不是仅看单个动作的次数。来源：[ACSM 2026 抗阻训练指南更新](https://acsm.org/resistance-training-guidelines-update-2026/)（核对日期：2026-09-08）。

本应用没有把下列数字说成该文献的统一处方。每周三／四天、每次四个动作、8–12 次、休息 90／120 秒、保留 2–3 次能力、两次达标与 10% 档位限制，均为本应用便于解释、验证的简化策略。它们也不保证达到文献讨论的最佳周训练量。

## 排课

- 新手默认周一、三、五全身训练，每次下肢、推、拉、核心各一个位置。
- 中级／高级默认周一、二、四、六，依次上肢 A、下肢 A、上肢 B、下肢 B。每次四个位置。
- 新手允许改选三个不相邻的训练日，校验包含周日到下周一。中高级选四天。
- 未选日期都是休息日。今日推荐直接读取周计划，不另行生成训练任务。
- 仅使用 recommendation-reviewed、明确允许推荐且无已知图解差异的动作。目前有 23 个；全库 302 个仍可浏览。
- 检查所需全部器械，包括卧推凳、深蹲架等辅助条件，检查能力等级。缺少候选就显示缺失位置。
- 优先减少一周内动作重复，再按可用难度与稳定 ID 排序；单次不重复同一个动作。
- 主要肌群间隔按本地自然日差至少 2 天处理，并结合人体区域映射识别 Back／Lats 等重叠标签。它不等于精确 48 小时恢复判断，也不覆盖所有协同肌群疲劳。
- 过去的计划不当作实际训练。近期已完成记录参与恢复过滤；今天及之后的已排日程也参与过滤，并可接收前一周计划。
- 漏练不转移到次日。重新生成保留已过去及已完成的日条目，训练记录本身从不被生成函数修改。

## 组数、次数、休息

| 能力 | 增肌组数 | 减脂组数 | 次数 | 计时动作 |
| ---- | -------- | -------- | ---- | -------- |
| 新手 | 2        | 2        | 8–12 | 20–30 秒 |
| 中级 | 3        | 2        | 8–12 | 30–45 秒 |
| 高级 | 3        | 3        | 8–12 | 40–60 秒 |

复合动作休息 120 秒，其他类别默认 90 秒。计时动作使用 seconds 字段，不显示次数。距离／时长类型有独立返回分支，目前不进入自动排课候选。减脂模式不承诺高次数或某一动作能局部减脂。

## 负重与记录依据

- 自重不填写外加公斤数；弹力带不换算为公斤；不计负重动作独立处理。
- 外加／辅助重量缺少历史或器械标识时显示“待试重”。不会根据体重或等级推算公斤数。
- LoadContext 显式提供当前器械 equipmentKey 与实际可用重量档位，不能把不同机器的配重数字互相套用。没有档位时可以沿用已知重量，但不自动创造下一档。
- 只比较同档案、同动作、同器械标识、同计量口径的完成记录。当前参考日及未来记录不用于加重判断。
- 同一天多次记录只取最近一次；重复 ID 不算两次训练。最近记录的组未完成、数值无效或组间重量不同，会要求重新确认工作重量。
- 连续两个不同日期的记录，每次工作组数足够、全部达到本次次数上限、剩余能力至少 2 次且工作重量相同，才建议更高难度的一个档位。
- 外加重量增加为更难；辅助重量减少为更难。变化超过当前标示重量 10% 则保持。辅助重量为 0 时不除以零。
- 最近任一工作组未达次数下限，建议一个更轻松的已知档位；否则保持。计时动作仅沿用最近工作重量，不套用次数进阶公式。
- 每条负重建议带文字原因；使用历史时携带 basedOnRecordIds。人工输入的计划重量不伪装成历史依据。

第四阶段 UI 尚无训练记录录入和器械档位设置，因此首次计划的外加负重都是待试重。历史推荐分支已通过注入内存 Repository 和 LoadContext 的测试；第五阶段接入实际记录后调用这些接口。

## 手动调整与数据边界

今天及未来尚未完成的处方可调整组数、次数／时长范围、休息和适用的公斤数。组件提交给 Pinia，再由 Service 校验、保存到 Repository，成功后才替换页面数据。过去或已完成的条目不可调整。

调整仅修改计划，不创建训练记录。当前采用内存 Repository；同一 Pinia 应用共用一个 Service 实例，不同应用实例隔离。刷新重置；本地持久化在第五阶段实现。普通页面切换与同周日期变化保留已调整计划。显式重新生成或修改档案会重新计算今天及未来未完成的建议。

所有日程键使用本地 YYYY-MM-DD，日期运算通过独立工具处理，避免 UTC 切片导致跨日。页面每 30 秒以及窗口重新获得焦点时检查日期，跨周生成新计划。
